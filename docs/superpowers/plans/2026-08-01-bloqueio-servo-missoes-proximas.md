# Bloqueio de servo ativo em missões próximas (< 3 meses) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Block registering a Servo as ATIVO in a Missão when the same person is already ATIVO in another Missão less than 3 months away (by a new, separate date field), unless a SUPER-issued one-time release code is provided.

**Architecture:** Two new optional fields on `Missao` (`mes`, `anoCalendario`) carry the real calendar date used only for this proximity check — the existing `ano` edition number is untouched. A new `LiberacaoConflitoServo` table stores short-lived 6-digit codes. A shared helper computes conflicts; `criarServo`, `atualizarServo`, and `adicionarServoRapido` call it before writing an ATIVO servo and return a `conflito` payload instead of saving when blocked. A SUPER-only action generates the release code and pushes it via the existing Pushbird integration. Two UI surfaces (the servo create/edit forms, and the quick-add modal) show the conflict and a "solicitar liberação" + code-entry flow.

**Tech Stack:** Next.js 16 App Router, TypeScript, Prisma + SQLite, React 19 `useActionState`, existing `notificarPushbird` (`src/lib/notificacoes.ts`). No automated test framework exists in this repo (no jest/vitest) — verification is done via throwaway `tsx` scripts against the dev DB (matching `scripts/import-excel.ts` convention) plus manual browser checks.

## Global Constraints

- Do NOT change the meaning or values of `Missao.ano` (edition number, e.g. 22, 23) — it stays exactly as-is and is unrelated to the new date fields.
- `mes`/`anoCalendario` are optional (`Int?`). Any missão missing either one must be treated as "no date" and never participate in a conflict (this covers all 21 historical missions with no date data).
- Conflict distance rule: `Math.abs((anoCalendarioA - anoCalendarioB) * 12 + (mesA - mesB)) < 3` counts as a conflict.
- Conflict check only applies when the Servo being saved will have `status === "ATIVO"`.
- Release codes are single-use, expire 15 minutes after creation, and are scoped to one `(pessoaId, missaoId)` pair.
- Follow existing code conventions: server actions live in `src/lib/actions.ts`, forms needing client state use `useActionState` (see `src/app/login/page.tsx`, `CriarUsuarioForm.tsx` for the pattern), data fetched server-side is passed down as props (not as JSX children) into client components.
- Every write-side action must call `requireUser()` (or `requireRole("SUPER")` for SUPER-only ones), matching every existing action in `src/lib/actions.ts`.
- Run `npx tsc --noEmit` after each task that touches TypeScript files to catch type errors before committing.

- [ ] **Step 1: Write the helper file**

Create `src/lib/conflitoServo.ts`:

```ts
import { db } from "./db";

export type ConflitoServo = {
  missaoConflitoId: number;
  missaoConflitoNome: string;
  distancia: number;
};

// checa se `pessoaId` já é servo ATIVO em outra missão a menos de 3 meses de `missaoDestinoId`.
// só compara missões que tenham `mes` e `anoCalendario` preenchidos — sem essa data, a missão nunca conflita.
export async function checarConflitoServo(
  pessoaId: number,
  missaoDestinoId: number
): Promise<ConflitoServo | null> {
  const destino = await db.missao.findUniqueOrThrow({ where: { id: missaoDestinoId } });
  if (destino.mes == null || destino.anoCalendario == null) return null;

  const outros = await db.servo.findMany({
    where: { pessoaId, status: "ATIVO", missaoId: { not: missaoDestinoId } },
    include: { missao: true },
  });

  for (const s of outros) {
    const m = s.missao;
    if (m.mes == null || m.anoCalendario == null) continue;
    const distancia = Math.abs((destino.anoCalendario - m.anoCalendario) * 12 + (destino.mes - m.mes));
    if (distancia < 3) {
      return { missaoConflitoId: m.id, missaoConflitoNome: m.nome, distancia };
    }
  }
  return null;
}

export function gerarCodigo6Digitos(): string {
  return String(Math.floor(100000 + Math.random() * 900000));
}
```

    distancia: number;

export default function ServoFormClient({
  action,
  pessoaNome,

}: {
  action: (prevState: unknown, formData: FormData) => Promise<ConflitoState | void>;

    setSolicitado(true);

              />
            </>
          )}

      )}

  );
